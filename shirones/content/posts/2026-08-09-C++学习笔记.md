几乎是从零重新学了一下C++。C++的输出和C语言、C#都不太一样。C++把数据之间的传输操作称作流。每个流都是一种与设备联系的对象。std::cout就是典型的输出流,在教材中通常和std::endl搭配使用，用以换行，但初学者往往会疏漏std::endl还有强制刷新缓冲区的作用。

std::endl 做了两件事：

插入一个换行符 \n

调用 std::flush，强制把缓冲区内容立刻写到屏幕

显然std::endl比\n换行的开销大上不少，每次 std::flush 都是一次系统调用（把数据从程序内存推到操作系统 → 推到终端）。

缓冲区（buffer） 本质上就是一块内存数组。程序往里写数据，攒够一批再统一推到屏幕上。相比于CPU和内存来说，I/O操作慢了几个数量级，缓冲区的存在可以减少计算机在I/O上消耗的时间。

std::endl的内部实现是这样的：
template<class CharT, class Traits>
std::basic_ostream<CharT, Traits>& endl(
    std::basic_ostream<CharT, Traits>& os)
{
    os.put('\n');       // 第一步：写一个换行符
    os.flush();         // 第二步：强制刷新 — 立刻把缓冲区推到屏幕
    return os;
}

std::cout << std::endl; 等价于 std::cout << '\n' << std::flush;

std::flush通过调用底层缓冲区的 pubsync()，把缓冲区里的数据立刻通过系统调用（Windows 上是 WriteConsole 或 WriteFile，Linux 上是 write）推给操作系统。系统调用不是普通的函数调用，计算机要从用户态切到内核态，CPU要保存上下文、切换特权级别、再切换回来。特别在循环语句中对性能的开销很大。

作为一个游戏开发者，对于性能的敏感应该做到习惯里，只有需要立即看到输出的情况才应该使用std::endl，比如std::cout提示输入时。不够std::cout 和 std::cin 之间有一个特殊机制：std::cin 被使用时，通常会自动先 flush std::cout（它们通过 tie 绑定在一起），std::endl就更加没有使用的必要了。

关于输出流的思考，我不禁想到C++23 引入了print头文件，他把C++的输出做的和python一样。

std::print("hello, {}!", name);       // 输出，不换行
std::println("hello, {}!");           // 输出 + 自动加 \n

它直接解决了 std::endl 的问题

std::endl 之所以存在并流行，一部分原因就是 iostream 的 API 没法方便地表达「换行」——你得额外写一个 << 操作符。而 std::endl 恰好同时做了两件事（换行 + flush），名字又叫 endl（end line），初学者自然以为它就是「换行」的代名词。

std::println() 从名字上就把语义厘清了：print + line = 打印一行，换行结束。不 flush，不意外，干净利落。你不再需要纠结 \n 好还是 std::endl 好——println 就是正确答案。

它摆脱了 iostream 的历史包袱
iostream 是 90 年代的设计。它背着一套庞大但没人用的 locale（本地化）系统，每次输出都要检查区域设置，即使你只是打印一个数字。这些开销在大多数程序里完全是浪费。

std::print() 用 std::format 做底层——现代、轻量、类型安全。不做你不关心的 locale 检查，性能明显更好。

格式化终于不再丑陋

// iostream 时代：写个带精度的浮点数
std::cout << std::fixed << std::setprecision(2) << 3.14159 << '\n';
// 需要记住 setw、setprecision 这些 manipulator，状态还会泄漏到后续输出

// print 时代：
std::println("{:.2f}", 3.14159);
// Python 风格的格式字符串，一目了然，不污染状态

std::print 做的事情其实很简单：把「输出内容」和「如何格式化」用一个字符串描述清楚，然后用最轻量的方式推到终端。事实证明iostream的设计假设并不完全正确，导致多余的开销，C++23距离广泛使用还有一段时间，不过我认为这种python风格的c++输出在未来会成为主流。
