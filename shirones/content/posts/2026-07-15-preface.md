## 关于这个时间戳的我

我是一名双一流软件工程专业学生，目标是靠游戏开发养活自己。目前的学习方向主要是 Unity Client Dev，有学长给出的学习路线参考，但是大一开学后 10 月份才正式接触游戏开发，算法也不怎么会，目前的 Dev 工作还高度依赖 Claude Code 以及 Codex 这样的 Agent 工具辅助，似乎近一年总在迷茫和探索中，没怎么静下心来学习。

刚开学时，到学校图书馆逛了一圈，速览过《Unity 游戏开发实战》，目前会基础的 C#、C、C++ 语法，《大话设计模式》还没看完，数据结构没有过系统学习，开学会跟着教学进度学。游戏开发中用到的数学基础还算够用，高等数学上下、线性代数、离散数学都修完了，也与应用进行了对照，比方说：Update 就是微分，引擎中旋转用四元数、欧拉角，引擎内部的缩放、旋转、平移使用矩阵变换，寻路算法用到图论。目前正在建立软件工程思维，也在实践 gitflow 工作流。

仿照教程抄过两个小游戏，了解 Monobehaviour 类的生命周期和回调函数以及基本的引擎 API 使用。Agent 也帮我写过 Editor 工具，还蛮好用。目前对 LLM 这类 AI 工具在游戏创作上的应用感兴趣，用于编码方面的学习过：Skill.md 和 MCP 就是说明书和格式规定协议，分别用来告诉AI怎么做和约束AI生成指定格式的对其他软件的控制代码；其他的 AI 工具研究的不多，OpenClaw 我没研究，没什么计算机基础，不敢折腾电脑系统。

对于 Unreal Engine 5 这类重型工业化的引擎也比较感兴趣。

内存管理上，我看过 .NET 的 Garbage Collection，知道有 3 代和 LOH，知道线程栈和托管堆。对象池模式是为了解决堆上内存碎片化的问题，不过暂时没写过几次。

我之前学 C++ 的时候也和 C# 进行了对比，比如 struct 和 class 在 C++ 中只有成员变量的默认可调用范围不同，而 C# 中一个是值类型一个是引用类型，性能开销不同。商业游戏以性能为第一要素，C++就是以高性能占据游戏开发的半边天，C#在.NET的加持下性能接近C++，xLua因为内存占用极小而且是解释型语言，其虚拟机也十分轻量，常用于热更新。计算机图形学方面，我知道线性代数的变换矩阵是为了计算下一帧的图像，也知道光栅化、网格这些概念。

最近在研究 3C，Cinemachine 比较好用，Virtual Camera 的设计理念我觉得很棒。我知道相机有正交相机和投影相机。四元数解决万向节锁。泰特-布莱恩角，Unity 引擎的旋转顺序是 YXZ，而 Unreal Engine 5 的旋转顺序是 ZXY，三维的转动顺序是有影响的。

Control 方面，我知道 Unity 有两套输入系统。UI 方面我知道 UGUI 原本是社区作品后来作者被收编，也知道有 DOTween 这种好用的插件。我知道 Unity 有一种高性能的写法叫 DOTS，是一种 ECS，不过具体我没看懂，也没多看。物理系统方面，我知道很多都是用公式去模拟，比如移动的逻辑就是修改 transform 的 position 或是 rigidbody 的 velocity。我知道有一个东西叫布娃娃系统，不过我没用过。Unreal Engine 的 gameplay 我知道有 GAS ，也还是刚刚学习的地步。

马上大二了，我会与华夜工作室的大家，教大一新生从基础开始搓小游戏，顺便补补我自己的基础。

我可能还有很多关于计算机基础、虚拟机、Linux、AI 相关的基础知识要学...持续努力ing。
